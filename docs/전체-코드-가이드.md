# 전체 코드 가이드

이 문서는 [market-data-pipeline-spec.md](/Users/heejunkim/Desktop/alfaka/docs/market-data-pipeline-spec.md)의 데이터 흐름을 실제 코드 위치와 연결해 보는 안내서입니다.

현재 임시 화면과 임시 확인 API는 제거했습니다. 차트 구현은 `apps/chart-engine`, 과거 조회 API와 실시간 push는 `services/07-api-websocket` 아래에 들어올 자리만 남겨두었습니다.

## 1. 한 줄 흐름

```text
Alpaca -> 01-alpaca-connector -> Kafka Raw -> 03-flink-stream-processor/Flink -> Processed Kafka -> Redis/S3/ClickHouse -> 07-api-websocket -> Chart Engine
```

## 2. 핵심 Topic

Raw topic:

```text
market.raw.bars
market.raw.updated-bars
market.raw.trades
```

Processed topic:

```text
market.ticks.v1
market.candles.live.1m.v1
market.candles.closed.v1
```

MVP에서 Alpaca WebSocket은 `bars`, `updatedBars`, `trades`만 구독합니다. `quotes`, `dailyBars`, `statuses`, `lulds`는 제외합니다.

## 3. 파일 구조

```text
config/market-data-request.json          구독 채널/기본 심볼/회사명 매핑
services/01-alpaca-connector/            Alpaca 시세/주문 외부 연동
services/02-kafka-event-publisher/        Kafka 이벤트 발행 계약
services/03-flink-stream-processor/       Raw -> Processed + Redis 로컬 처리/Flink 계약
services/04-redis-state-store/            Redis 캐시/상태 저장 계약
services/05-clickhouse-store/             ClickHouse 저장/조회 계약
services/06-s3-store/                     S3 Raw/Processed 저장
services/07-api-websocket/                Chart API / WebSocket Gateway placeholder
apps/chart-engine/                       Chart Engine placeholder
packages/alfaka/alpaca/                  Alpaca 구독/수집/백필 코드
packages/alfaka/streaming/               정규화, live candle, 5m/10m, MA 계산
packages/alfaka/storage/                 S3 저장 코드
packages/alfaka/common/                  env, Kafka, S3, secret 공통 코드
infra/clickhouse/initdb/                 ClickHouse 로컬 schema
flink-jobs/market-data-normalizer/        운영 Flink job 계약
```

## 4. 설정 흐름

`.env`는 실제 키가 들어가는 로컬 전용 파일입니다. repo에는 예시 `.env`를 두지 않습니다.

로컬 실행 시 Docker Compose가 아래 서비스에 `.env`를 붙입니다.

```text
services/01-alpaca-connector/market_stream.py
services/01-alpaca-connector/historical_backfill.py
```

주요 값:

```text
APCA_API_KEY_ID
APCA_API_SECRET_KEY
ALPACA_FEED=sip
ALPACA_SYMBOLS=AAPL,TSLA,NVDA
ALPACA_CHANNELS=bars,updatedBars,trades
HISTORICAL_DATA_KIND=bars 또는 trades
HISTORICAL_SYMBOLS=AAPL,TSLA,NVDA
HISTORICAL_START=...
HISTORICAL_END=...
```

## 5. Alpaca 구독 요청

관련 파일:

```text
config/market-data-request.json
packages/alfaka/alpaca/subscription.py
scripts/local/preview-subscription.py
```

회사명이나 심볼을 받아 최종적으로 아래 형식의 Alpaca 구독 JSON을 만듭니다.

```json
{
  "action": "subscribe",
  "bars": ["AAPL"],
  "updatedBars": ["AAPL"],
  "trades": ["AAPL"]
}
```

확인:

```sh
PYTHONPATH=packages python scripts/local/preview-subscription.py AAPL
```

## 6. 실시간 수집 흐름

관련 파일:

```text
services/01-alpaca-connector/market_stream.py
packages/alfaka/alpaca/websocket_collector.py
packages/alfaka/common/market_messages.py
```

흐름:

```text
Alpaca WebSocket
  -> raw message 수신
  -> Raw Envelope 생성
  -> market.raw.bars / market.raw.updated-bars / market.raw.trades에 저장
```

Raw Envelope:

```json
{
  "source": "alpaca",
  "feed": "sip",
  "channel": "trades",
  "symbol": "AAPL",
  "eventTime": "2026-06-25T10:15:20.100Z",
  "receivedAt": "2026-06-25T10:15:20.130Z",
  "raw": {}
}
```

실제 Alpaca 수집기 실행:

```sh
docker compose --profile alpaca up -d --build
docker logs -f alfaka-alpaca-ingestor
```

## 7. 스트리밍 처리 흐름

관련 파일:

```text
services/03-flink-stream-processor/local_main.py
packages/alfaka/streaming/processor.py
packages/alfaka/streaming/transforms.py
```

로컬에서는 `local-stream-processor`가 Flink 역할을 흉내 냅니다. 운영에서는 이 계약을 `flink-jobs/market-data-normalizer` 기준으로 Flink에 옮깁니다.

처리 규칙:

```text
trades       -> market.ticks.v1 + market.candles.live.1m.v1
bars         -> market.candles.closed.v1의 1m 확정 캔들
updatedBars  -> 같은 symbol/interval/timestamp 확정 캔들 보정
1m bars      -> 5m/10m 확정 캔들 집계
closed close -> ma5/ma20/ma60 계산
```

Redis key:

```text
price:{symbol}:latest
candle:{symbol}:1m:live
candle:{symbol}:{interval}:latest
candles:{symbol}:{interval}
```

`updatedBars`는 같은 timestamp의 Redis series 항목을 지우고 새 확정 캔들로 교체합니다.

## 8. 과거 데이터 백필 흐름

관련 파일:

```text
services/01-alpaca-connector/historical_backfill.py
packages/alfaka/alpaca/historical_backfill.py
```

흐름:

```text
Alpaca Historical REST -> Raw Envelope JSONL -> S3/MinIO
```

S3 Raw 경로:

```text
market-data/raw/source=alpaca/channel=bars/symbol=AAPL/year=2026/month=06/day=25/hour=10/part-000001.jsonl
market-data/raw/source=alpaca/channel=trades/symbol=AAPL/year=2026/month=06/day=25/hour=10/part-000001.jsonl
```

실행:

```sh
docker compose --profile backfill run --rm historical-backfill
```

## 9. S3 저장 흐름

관련 파일:

```text
services/06-s3-store/processed_sink.py
packages/alfaka/storage/processed_s3_sink.py
```

흐름:

```text
market.ticks.v1
market.candles.live.1m.v1
market.candles.closed.v1
  -> S3/MinIO processed 경로
```

Processed 저장 기본값은 Parquet입니다. 로컬 디버깅이 필요하면 `S3_PROCESSED_FORMAT=jsonl`로 바꿔 JSONL 저장도 가능합니다.

## 10. ClickHouse 역할

관련 파일:

```text
infra/clickhouse/initdb/01-market-data.sql
scripts/local/check-clickhouse.sh
```

ClickHouse는 S3에 쌓인 과거 데이터를 빠르게 조회하기 위한 분석/조회 DB입니다. 로컬 Docker에서는 schema와 조회 계약을 검증하는 용도입니다.

## 11. Chart API가 붙을 위치

관련 폴더:

```text
services/07-api-websocket/chart-api/
```

책임:

```text
GET /api/charts/candles
Redis 최근 캔들 우선 조회
Redis에 없는 구간은 ClickHouse 조회
누락 구간은 Alpaca Historical REST 백필로 보완
```

응답은 차트 엔진이 바로 쓸 수 있게 candle, volume, ma5, ma20, ma60을 포함합니다.

## 12. WebSocket Gateway가 붙을 위치

관련 폴더:

```text
services/07-api-websocket/websocket-gateway/
```

출력 메시지:

```text
LIVE_CANDLE_UPDATE
CANDLE_CLOSED
CANDLE_CORRECTED
TRADE_TICK
```

실시간 이벤트의 canonical source는 Kafka Processed Topic입니다. Redis는 최신값과 최근 시리즈 캐시로 사용합니다.

## 13. Chart Engine이 붙을 위치

관련 폴더:

```text
apps/chart-engine/
```

차트 엔진은 Alpaca 원본, Kafka Raw, Redis 내부 key를 직접 몰라도 됩니다.

차트 엔진이 보는 것은 두 가지입니다.

```text
초기 로딩: Chart API REST 응답
실시간 반영: WebSocket Gateway 메시지
```
