# AI 답변 SSE 지연 측정 (이슈 #43)

측정 스크립트: `scripts/benchmarks/agent_sse_latency.py`

## 공통 조건
- 환경: 로컬 Docker (Kafka·Redis·ClickHouse·백엔드·분석 워커·전달 게이트웨이), 실제 OpenAI `gpt-5.2` 호출
- 근거 데이터: 로컬에 적재한 SEC 공시 (AAPL, MSFT, NVDA)
- 질문: 유형 3개(수익성·재무 구조·현금흐름) × 종목 3개 = 9개, 각 5회 = 45회
- 캐시: 요청마다 `gops:agent:analysis:*`, `gops:agent:financial-final-answer:*`를 비워 미적중 경로만 측정
- 시각 기준: 클라이언트가 요청을 보낸 시각부터 SSE 이벤트가 도착한 시각 (`time.perf_counter`)
- "첫 글자" = `delta` 이벤트가 있으면 첫 delta, 없으면 본문 요약이 들어 있는 첫 `report`

|---|---|---|---|---|

- before-5s에서 "합성 LLM 답"만 모은 값은 JSON의 `*_llmAnswerOnly`에 있다.

## 합성 LLM 경로만 비교 (`summarize_agent_sse_latency.py`)
9개 질문 중 4개(재무 구조 MSFT, 현금흐름 AAPL·MSFT·NVDA)는 근거 부족으로 합성 LLM 단계에 가지 않고
"추가 확인 필요" 기본 답변(또는 빈 답변)으로 끝난다. 스트리밍과 무관하므로 전후 비교는 `financial-synthesis`
호출이 있었던 5개 질문 × 5회 = 25회만 쓴다.

| 조건 | 합성 폴백 | 첫 글자 평균/중앙값/최대 (ms) | 완성 평균/중앙값/최대 (ms) |
|---|---|---|---|
| before-5s (운영 설정) | 25/25 | 5435 / 5401 / 6145 | 5435 / 5401 / 6145 |
| after-5s (운영 설정) | 0/25 | 2005 / 1965 / 2853 | 17863 / 18254 / 22195 |
| before-120s (타임아웃 해제) | 0/25 | 18023 / 18560 / 21210 | 18023 / 18560 / 21210 |
| after-120s (타임아웃 해제) | 0/25 | 2053 / 1942 / 2934 | 18300 / 18545 / 24468 |

읽는 법
- before-5s는 합성 LLM이 5초 안에 끝난 적이 한 번도 없어서 25회 모두 기본 답변으로 대체됐다. 사용자는 LLM 답변을 받지 못했다.
- before-120s는 "5초 제한이 없었다면"의 값이다. 운영 설정이 아니다.
- after는 LLM 답변이 끝나기 전에 첫 문장부터 보여 준다. 완성 시각은 거의 그대로이고(LLM 생성 시간), 달라진 것은 첫 글자 시각이다.
- after의 완성 시각은 delta를 문장 정화 때문에 끝 64자를 보류해도 report 이벤트 기준이라 영향이 없다.
